# ab股

> 模拟盘交易系统记录库：A 线逆向网格 + B 线半日线 + T+0 影子训练。
> 本仓库只记录规则、操作与模拟盘结果，**不是实盘成绩，不构成投资建议**。
> 所有金额单位为人民币元；所有交易均为模拟盘交易。

## 项目目的

把从 2026-10-13 开始讨论、执行、纠错的一套模拟盘系统，整理成一份可以查找、修改、整体迁移的记录：

- 规则变了，在哪里改、改了什么、为什么改，都有据可查；
- 数字变了，以台账为准，不把快照、推断当成交；
- 换一台机器、换一个人接手，能按本文档把系统原样搭起来（除账号与密钥需重新配置，见“迁移”一节）。

## 如何查找与修改

1. 改规则：先改本文档对应章节，再改技能/任务文件，最后在 `CHANGELOG.md` 记一笔（日期、改了什么、谁定的）。
2. 改数字：只改 `data/` 快照与台账来源，不改历史结论里的旧数字；旧数字错了就加“修正说明”，不静默覆盖。
3. 查一次交易：先查 `data/snapshot-2026-10-26.md` 的聚合数，再按来源文件名回原台账核对批次、价格、时间。
4. 查一次事故：先查 [05 操作时间线与大事记](docs/05-操作时间线与大事记.md)，再查 [07 风险与待办](docs/07-风险与待办.md) 看它是否已闭环。

## 如何迁移到新环境（步骤清单，不含任何密钥）

1. 新建一个空的 GitHub 仓库（仓库名建议 `ab-gu`，显示标题仍用“ab股”），把本目录全部文件推入。
2. 在新环境重建目录结构：规则文档、台账、技能、定时任务脚本分开存放，不混放。
3. 重新配置模拟盘账号与登录信息：所有账号、密码、API Key、验证码一律用新环境的安全存储重新录入，**本仓库不含任何密钥，旧环境的值不得复制过来**。
4. 重新配置行情数据源：按 [06 定时任务与脚本清单](docs/06-定时任务与脚本清单.md) 逐项核对数据源优先级与代理设置，逐项实测通过后再开任务。
5. 重新建立定时任务：按 [06](docs/06-定时任务与脚本清单.md) 的任务名、时间、用途逐一创建；创建后先做一次只读干跑（dry-run），确认窗口、标的、额度口径无误。
6. 迁移台账：把最近一期快照与原始台账文件一并带走；在新环境用额度脚本重算一次，核对批次成本与额度脚本口径差异（见 [07](docs/07-风险与待办.md)），差异写进新环境的修正说明。
7. 试运行一个完整交易日：早盘第 0 步补漏 → 08:00 挂单 → 09:20 复核 → 09:40 竞价复核 → 13:05 午盘 → 14:30 选股 → 收盘汇总，全程只读核对无误后，再恢复自动下单类任务。

## 保密与口径红线

- 本仓库绝不写入密码、API Key、验证码、手机号、邮箱、服务器 IP、SSH 密钥、真实券商账号口令；凡需配置处一律写 `<占位符>`。
- 数字找不到依据就写“未确认 / 待核对”，不编造。
- 浮亏、浮盈不作绩效；考核口径见 [04](docs/04-考核与统计口径.md)。
- 任务文件里仍有已过期的旧措辞（例如个别任务正文里的“盘中不监盘”），报告与执行一律按现行规则（2026-10-22 起盘中止损监盘），改任务正文须走完整读取与确认流程，不得只改一半。
