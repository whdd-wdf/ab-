# 搭建执行技能：只凭 GitHub 文档在笔记本上从零搭建操作侧脚本

> 用途：只凭 GitHub 仓库文档，在笔记本上用带工具闭环的编码 agent 从零写出操作侧四脚本并跑通验证。2026-11-13 实测通过（Claude Code + DeepSeek-V4.1-Flash，基线 36/36、对接全过、调试 0 轮，commit 80554f0）。
>
> 依据：`docs/实施记录/laptop_build_plan_20261113.md`（预案，含模型/提示词/agent 评估与搭建流程）与 `docs/实施记录/ops_build_test_20261113.md`（笔记本搭建章节）。本技能是执行部分的单独提炼，作为指导；预案里的评估与推断过程见预案原文。

## 适用条件

- 任务：从零搭建操作侧脚本（合规 `order_compliance.py`、执行器 `order_executor.py`、门控 `gate_local.py`、成交监视 `fillwatch_rehang.py`），依据只许是 GitHub 文档与虚拟程序。
- 环境：笔记本（宏碁 Nitro 5，Ubuntu 24.04），FCC 网关在跑，Claude Code CLI 已装。
- 不适用：一次性 LLM 调用（盒内 qwen2.5:3b 与 qwen2.5-coder:7b 两轮已证伪，均 23/32 = 71.9% 止步）；本地 7–8B 模型作首选。

## 1. 模型

- **首选：DeepSeek-V4.1-Flash，经 FCC（Coarena `deepseek-v4-1-flash-1017`）**。完整模型 ID 为 `anthropic/custom_11c1cd762ab64b7abf5df581d358f2fb/deepseek-v4-1-flash-1017`。
- **关键教训（必须用完整前缀 ID）**：裸名 `deepseek-v4-1-flash-1017` 会被 Claude Code 标 `unrecognized_model` 并由 FCC 回退到默认模型 `nemotron-3-ultra-550b-a55b`（冒烟实测证实）；unrecognized_model 警告本身不影响路由，但模型会被换掉。核实方法：FCC 服务日志 `~/.fcc/logs/server.log` 的 `request.completed` 记录显示 provider 为 `custom_11c1cd762ab64b7abf5df581d358f2fb`、model 为 `deepseek-v4-1-flash-1017`。

## 2. 提示词：调试契约（五条，缺一不可）

1. **失败证据全文**：完整 traceback（文件、行号、函数名、错误类型与消息）+ 自测失败输出全文，不截断、不摘要。traceback 是定位的唯一可靠起点。
2. **调用链（显式写出，不让模型反推）**：沿 traceback 逐级列出调用链，例如执行器 `main L303 → process_one L236 → move_order L66`，并对链上每个函数写清：调用方传了什么实参、被调方收到了什么、被调方返回了什么、调用方拿到返回值后做了什么。契约以表格写出，不许只写“请检查调用”。
3. **接口契约表（从自测断言与接口规范抄，不许模型自己编）**：对链上每个函数，写清输入契约（参数名、个数、类型、含义）与输出契约（返回值类型、键名、含义），并注明契约来源（自测脚本哪一行断言、接口规范哪一节）。例如 fillwatch：自测取 `computed_orders` 键，契约表须写明输出字典必须含 `computed_orders` 键；执行器：`move_order` 须返回结果（调用方 `result.get("kind")` 依赖它），契约表须写明返回值不得为 None。
4. **根因先于改动**：模型在改任何代码之前，必须先用一句话写出根因（“根因是 X 调用 Y 时传了 Z，而 Y 期望 W”），并指明根因在哪一方（调用方 / 被调方 / 契约本身）。根因句须与 traceback 的行号对得上；对不上即判定未定位，不许改代码。
5. **最小改动 + 验证闭环**：只改不一致的一方，不重写无关代码；改完必须跑对应的自测（`python3 tests/test_<t>.py --base <virtual 目录>`），报通过数/总数；仍失败则回到第 2 条重做，最多 3 轮；3 轮未过即停，写清差在哪，不许硬编通过。

### 与盒内两轮提示词的区别

| 项 | 盒内两轮 | 本模板 |
|---|---|---|
| 契约 | 无，模型自己从代码里反推 | 显式契约表，从自测断言与接口规范抄 |
| 根因 | 无要求，模型直接改代码 | 根因句先于改动，须与 traceback 行号对上 |
| 工具/验证 | 一次性输出，机械替换，不跑测试 | 改完必须跑对应自测，报通过数，失败即迭代 |
| 重复 | 无机制发现自我重复（fixB2 与 fixB1 逐字节相同无人发现） | 每轮须先报上一轮改动与结果，重复输出即判定未定位 |
| 通过标准 | 自测脚本全文给了，但未要求模型逐项对断言 | 通过标准逐项列出，改完逐项核对 |

## 3. Agent：Claude Code（经 FCC）

- **首选 agent：Claude Code CLI 2.1.323，经 FCC 127.0.0.1:8082 作后端，模型用 DeepSeek-V4.1-Flash（Coarena 完整 ID，见 §1）**。
- 启动：`~/.local/bin/fcc-claude` 启动器（注入 FCC 代理环境），`-p` 非交互模式，stdin 传提示词，nohup 后台跑、短命令轮询。
- 安装（若未装）：`~/node-v22/bin/npm install -g @anthropic-ai/claude-code`（node 不在默认 SSH PATH 内，须用全路径）；装好后验证两件事再开工：①`claude --version` 能出版本号；②后端指向 FCC（`fcc-claude` 启动器按设计应指向 127.0.0.1:8082，装好后以实测为准，不预支结论）。若 `claude --version` 仍不可用，检查 npm 全局 bin 目录是否在 PATH 内（用 `~/node-v22/bin/npm root -g` 查，再把该 bin 目录加进 PATH 或用全路径调 `claude`）。
- 备用 agent（按顺序）：① `fcc-aider` / `fcc-opencode`（笔记本 `~/.local/bin/` 现成）：同为带工具循环的编码 CLI，走 FCC 同一路；若 Claude Code 装不上或跑不起来，改用其中之一，工具清单与迭代循环不变。② 沙箱驱动的工具循环（最后兜底）：沙箱侧写驱动脚本，经 FCC/dsh API 调模型，读文件与跑测试经 `laptop_ssh.sh` 在笔记本上做，改代码由驱动按函数名替换后跑测试验证；仅当笔记本上所有 agent CLI 都不可用时才用。
- 明确不用的路：盒内的一次性 LLM 调用（已两轮证伪）；本地 `qwen3:8b` 作 agent 模型（与已失败的 7B 同量级，不作首选，见 §1）。

### 工具清单与迭代循环

- 工具清单（缺一不可）：Read（读文件：文档、脚本、自测、traceback）、Edit（改代码：按函数名或行号最小改动）、Bash（跑命令：`py_compile`、自测、虚拟程序 init/submit/run/snapshot、quota/log 核对）、TodoWrite（可选，记轮次与通过数）。
- 迭代循环（每轮）：
  1. 跑对应的自测，取完整失败输出。
  2. 读 traceback，沿调用链读调用方与被调方，填 §2 的契约表。
  3. 写根因句（须与 traceback 行号对上），否则停下重读，不改代码。
  4. 最小改动（只改不一致的一方）。
  5. 重跑对应自测，报通过数/总数；通过即进下一步，未通过即回第 1 步。
  6. 每 bug 最多 3 轮；3 轮未过即停，写清差在哪，不许硬编通过。
- 纪律：沙箱侧不代写代码、不给确定性补丁；调试须由笔记本上的 agent 自己用工具迭代完成；每轮产物用轮次后缀区分（`fixC1/`、`fixC2/`…，防覆盖）；agent 的每轮改动、根因句、自测通过数须记入日志。

## 5. 风险与已知坑（搭建前须读）

- FCC 非流式 500 bug：调用方一律 `stream=true`（Claude Code 经 FCC 时须确认其流式设置；若 agent 调模型报 500，先查是否走了非流式）。
- Ollama 只绑 Tailscale IP（100.90.180.87:11434），不绑 localhost；agent 若调本地 Ollama 须用该地址。
- dsh 网关为 nohup 运行，重启不自动恢复；使用前确认端口 18900 仍在监听。
- `laptop_ssh.sh '<命令>'` 形式脚本不接受（报 cannot parse host），须用 `laptop_ssh.sh madaha@100.90.180.87 '<命令>'`。
- 笔记本 git 是重定位安装：`~/.local/bin/git`，须设 `GIT_EXEC_PATH=~/.local/git-pkg/usr/lib/git-core`；默认 exec-path 指向不存在的 `/usr/lib/git-core`，git push 报 `'remote-https' 不是一个 git 命令`。
- 笔记本仓库无 GitHub 凭据（无 credential.helper、无 .netrc/.git-credentials、`~/.ssh` 只有 authorized_keys 无私钥、gh 未安装、无 GITHUB_TOKEN），且默认解析的 github.com（57.155.223.240）443 不通；推送失败时先核对本地与远端 HEAD，不强推、不改历史；凭据补齐后须先合并/变基再推（远端可能已多一个提交，呈 1↔1 分叉）。
- 门控窗口：自测与对接若在 17:05 之后跑，真实时间基线会因窗口已过而失败（执行器 gate-closed、虚拟 run 不成交），非脚本 bug；真基线与对接可用 `PYTHONTZPATH=/tmp/faketz/zone`（ZoneInfo('Asia/Shanghai') 被替换为 UTC0 的假时区文件，假本地时间约 09:18–09:19，与真实日期同一天），脚本本身不改；须如实记录假时间口径。
- 笔记本 Chrome 常驻但本次不碰浏览器执行层（`laptop_order.py` 不在验证范围内，只验脚本、不实测下单）。
- 沙箱侧不代写代码、不给确定性补丁；调试须由笔记本上的 agent 自己用工具迭代完成。
- 盒内两轮的教训：段顺序影响名字定义（helpers 段须在 `if __name__` 段之前）；缺 `__main__` 入口致静默退出；datetime 类/模块名冲突；非标准库 import；CLI 参数形式须与真实一致。这些已补进接口规范 §8.1，搭建时须逐项核对。

## 6. 实测记录
