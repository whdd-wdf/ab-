## 4. 根因与改进建议

1. **3B 小模型多位数小数运算不可靠**：涨幅 6/8 错，P4、股数、金额、仓位占比接连算错。不是偶发笔误，是系统性算术弱。建议：①关键数字（涨幅、金额、P4）改由程序算、AI 只做判断（即“程序验算 + AI 决策”分工，AI 不再手算）；或②换更大模型/更强推理服务；或③给 AI 一个计算器工具（盒内 `python3 -c` 现成可用，提示词里允许 AI 先调计算器再写结论）。
2. **表格跨行串位**：44.11 从 603198 行串到 000596 行。建议：提示词里把候选股拆成“一次一只”的独立小任务，或要求 AI 在定稿前复述一遍所选股票的“代码—名称—现价”三元组并逐字比对。
3. **规则误读**（涨幅≤5% 被当成“须下跌”）：建议提示词里给一条正例+一条反例（如“涨 +1.4% 符合，涨 +6% 不符合”），不要只给公式。
4. **合规清单缺“买价≈现价”项**：程序与 AI 都拦不住错价单。建议虚拟程序 §1.5 与接口文档各补一项 B 线买入校验：买价与现价偏差超过一个 tick/一定比例即拒绝（真实系统里买价远低于市价只会不成交、无损失；虚拟“合规即成交”放大了危害，补这一项才能让虚拟演练保真）。
5. **辩论缺数据复核环节**：评判应先复核三方引用的数字（买价、现价、金额）与行情表是否一致，再裁决；或在评判前加一道程序自动复核（数字对不上直接打回重算，不进入裁决）。
6. **成交确认自相矛盾**（第 3 项说没有成交行、结论却说已确认）：建议确认步骤拆成“先逐行抄出 trade_log 尾部、再比对订单号”的强制格式，结论须与逐项一致。
