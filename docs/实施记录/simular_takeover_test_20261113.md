## 6. 过程问题与接口文档的不足

### 6.1 盒内 AI 的工程限制（本次实测）

1. **单次长提示词不可用**：全文约 29K token 的单次提示词，Ollama 在 CPU 上预填充约 10 分钟后报 HTTP 500（02:56:14，`POST /api/generate` 500，10m40s）。改用分段提取后才跑通。
2. **长生成会 500**：不限长时，某段提取生成到 1909 token 仍未停，6m40s 后报 HTTP 500。把 `num_predict` 限为 800 后，chunk 2/3/4 均一次成功；但 chunk 4（§9–§16）在内存吃紧时仍于生成 341 token 后报 500，重启 Ollama 释放内存（6.7GB→2.5GB 已用）后才成功。**根因是盒子内存不足**：7.7GB 总内存，Ollama 模型 1.9GB + KV 缓存随请求累积，数次请求后可用内存只剩约 1.0–1.4GB，极易触发 500。每次大请求前重启 Ollama 是有效但笨拙的 workaround。
3. **慢**：4 段提取 + 1 次综合 + docs/01 前半段，合计约 1 小时；其中 docs/01 后半段（12K token）预填充 6 分钟、生成 435 token 后再次 500，未能完成。盒内 3B CPU 模型只适合“分段读 + 短输出”，不适合一次性读 700 行文档并输出长报告。
4. **提取质量尚可但有重复**：4 段要点提取基本准确（见附录），但 chunk 4 有重复条目（第 12/15 条相同，第 17–20 条相同），且 chunk 2 第 8–10 条对 `.trading_day` 的表述有轻微绕口。3B 小模型在长文档上会出现重复与啰嗦。

### 6.2 接口文档哪里不够用

1. **分工的主体划分不够醒目**：AI 把操作侧的华为脚本（`fillwatch_rehang.py`、`huawei_bookings.csv`）误认作管控侧。接口规范 §0.1 虽写了两分法，但“管控 = AI 本身、操作 = 华为/笔记本脚本”这一主体对应关系没有用一句话钉死、也没有一张“谁是谁”的对照表。建议在 §0.1 顶部加一句：**“管控侧的唯一主体是接管 AI（读数据、做判断、发指令）；华为 VPS 与笔记本上的全部脚本、文件、定时器都是操作侧，接管 AI 只读它们、绝不把它们当成管控侧。”**
2. **检查项缺判定标准**：§10 每日工作流列了步骤，但 AI 输出的检查项仍停留在“读什么文件”。建议 §10 每项后补“判据”（例如：快照 stale 超 5 分钟即告警、quota 平衡恒等式不通过即停、P1-2/P1-3/P1-4 模式须与当日记录一致），让接管 AI 知道“读完之后算什么、什么算通过”。
3. **核对须给算例**：AI 面对“卖价是否等于节点价×1.02”时没有动手算。接口规范 §1.5 合规清单列了规则，但没有给一个带数字的完整算例（例如：节点 48.61 → 卖价 49.58 → 金额 9,916 → 延时 4:54）。建议在 §1.5 后附一个“601088 真实算例”，让接管 AI 照着算一遍，降低“只复述问题、不动手算”的概率。
4. **实时数据缺口是结构性的**：`trade_log.csv` 实时数据、`quota.py` 实时输出、fillwatch 快照实时流都不在 GitHub 仓库里。接口文档再完善也补不了这个缺口。接管 AI 要真正监管，必须另给一条实时数据通道（例如：只读同步 trade_log/quota/快照到一个接管 AI 可读的位置，或明确说明“接管时须先开通华为只读通道”）。建议在 §9“接管前必读”里加一条：**“实时数据不在仓库里；接管前须确认 trade_log、quota、fillwatch 快照的只读读取路径，否则只能做离线推演、不能做实时监管。”**

## 7. 结论

- **能否建立监管**：**逻辑上部分跑通、尚未完全跑通**。盒内 AI 读完了接口规范全文（分段）、能列出系统分工与检查项、能指出 trade_log 实时数据不在仓库里这一关键缺失——说明接口文档作为“接管依据”是基本够用的，别的 AI 可以按它理解系统结构。但它在三个关键点上不合格：①分工主体划分错误（把操作侧华为脚本当成管控侧）；②检查项缺判定标准；③601088 核对只复述问题、未动手验算。按当前接口文档 + 盒内 3B 模型，**能建立“离线推演式监管”，不能建立“可落地的实时监管”**。
- **接口文档是否够用**：**基本够用，但有 4 处须补**（见 §6.2）：分工主体一句话钉死、检查项补判据、合规清单附真实算例、§9 明确实时数据不在仓库里及接管前的只读通道前置条件。
- **盒子是否可用**：**可用，但只适合轻量概念验证**。4 CPU / 7.7GB 内存能跑 qwen2.5:3b，但长提示词与长生成会因内存不足报 HTTP 500，须分段 + 限长 + 适时重启 Ollama；单次大任务耗时以 10 分钟计。正式接管须用更大内存或更强的模型/服务。
