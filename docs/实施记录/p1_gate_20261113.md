## 3. 幂等与并行安全设计

- `enable --now` / `disable --now` 本身幂等；`rm -f` 标志不存在也不报错。
- 标志只在“缺失或 mtime 日期非当日”时才写（重复开门是真空操作，见 T3：
  mtime 分毫不差）；关门重复执行无事可做（见 T5）。
- 开门 `enable` 两次失败才返回 1，且**不写标志**（fail-closed，与沙箱 `&&` 链同义）；
  非交易日开门只做关闭扫尾、不移 pending。
- pending 移动（唯一写冲突点，沙箱 gate 与华为关门可能在同一分钟执行）：
  - 逐文件 `os.rename`；对端已移走的文件触发 FileNotFoundError → 记 skip、不报错（T7b）；
  - failed/ 已有同名文件时绝不覆盖，改存 `<name>.dup-<epoch>.json`（T7a，
    沙箱版原文原样保留）；沙箱 close 循环本身有 `[ -e "$f" ]` 守卫，反向同样安全。
  - 两个方向都不存在“重复移 pending”：文件一旦离开 pending 即不可再移。
- 本地并发：`flock`（`.gate.lock`，非阻塞）；抢不到锁直接 rc 0 静默退出（T11），
  由持锁方完成工作。沙箱 gate 不持锁，但它只做幂等操作 + 受上述逐文件保护的 mv。
- 标志竞写：沙箱 touch（07:25 实测）与华为 touch 都是“当日即有效”，mtime 只相差
  分钟级；华为开门见当日标志即跳过，不覆盖、不回写。
- 日志：`/root/monitor/gate_local.log`（dry-run 不写文件，只打 stdout）。

   migration_sync 不碰 `/root/monitor/`，venv 不会被同步覆盖或删除。
